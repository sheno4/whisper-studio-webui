# 浏览器缩放闪烁修复

缩放会同时改变 CSS 视口和 devicePixelRatio。原适配器会在 ResizeObserver 或独立的尺寸更新帧中重置画布，然后通过 invalidate 等待下一次光学绘制。ResizeObserver 在动画帧回调之后执行，清空后的画布可能先被浏览器呈现；顶层弹窗的玻璃副本也会一起消失。同一物理尺寸、不同 DPR 的缩放还会触发不必要的画布和纹理重建。

| 修改前 | 修改后 | 原因 |
| --- | --- | --- |
| 尺寸观察回调直接清空画布，下一帧重绘 | 运行期间只标记尺寸待更新，在同一次原版 render 调用前调整尺寸并立即绘制 | 避免将清空的绘制缓冲呈现到页面。 |
| DPR 改变时即使物理尺寸相同也重建缓冲、移除弹层材质 | 物理尺寸相同时复用缓冲，只更新 DPR、场景、几何和指针坐标 | 保留清晰度与正确坐标，减少无用分配。 |
| 适配器另开一条尺寸更新 RAF | 所有尺寸、滚动和 DPR 通知交给原版绘制循环 | 合并同一帧内的多个通知。 |
| inset 简写与 left/top 反复相互覆盖 | 逐项比较并更新定位长属性 | 避免相同尺寸更新继续触发材质观察器。 |

原版启动/恢复上下文时仍同步建立尺寸，供初始化指针使用。实际分配失败继续执行原有固定质量回退；渲染期间弹层请求降级只标记下一帧，避免产生第二条绘制循环。上游 Lens 源码、着色器、真实像素密度策略和后端业务保持不变。

验证使用隔离 Chrome、模拟 HTTP/SSE 数据和绘制调用元数据，按浏览器帧记录画布尺寸重置及完整默认帧缓冲绘制的先后顺序。覆盖视口与 DPR 联动、快速反向变化、打开设置时缩放；不读取像素、不截图、不使用图像识别，也不执行真实任务或保存设置。软件 WebGL 的数值结果不代表实际显卡帧率或视觉验收。
