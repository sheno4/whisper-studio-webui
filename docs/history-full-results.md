# 历史记录打开完整结果

2026-10-20 更新：下文“删除输出保留正文”及菜单“查看内容”描述的是此前实现，已由 [任务操作与完整删除](task-actions-deletion.md) 取代。当前菜单去掉重复查看入口，单项统一“删除任务…”，同时删除当前任务、历史、完整结果和生成文件；“仅清空历史记录…”仍明确保留当前任务及输出。

历史记录与刚完成的任务使用同一套阅读界面：原文、译文、双语、字幕分段、时间戳、查找、复制、日志、输出文件和导出。完成任务继续保留在当前任务中，除非用户主动移除；历史入口不再显示“已归档”的摘要页。

| Before | After | Why |
| --- | --- | --- |
| 历史仅保存名称、状态、时间和目录；没有当前任务时只能打开摘要页 | 完整结束结果独立保存，历史按需读取同一个阅读器 | 移出当前任务或重启服务后，正文、译文和日志仍可回看。 |
| 同 ID 重新执行时，历史会取正在运行的新任务 | 历史读取上次结束的结果，并使用独立的历史导出范围 | 防止显示或导出另一轮任务的内容。 |
| 两层逻辑均自动截掉第 50 条之后的历史 | 保留所有历史，由现有分页展示 | 完成新任务不再自动丢弃旧记录。 |
| 移出当前任务或清理旧上传可能删除历史使用的本地媒体 | 轻量历史索引保存输入引用，移出队列和上传清理都保留这些引用 | 不为回看历史丢失仍需使用的上传源文件。 |
| 删除输出后，详情缓存可能恢复已删除路径 | 同步清空文件引用，正文和日志保留，前端按目录/结束时间等版本重读 | 避免旧缓存重新显示已经删除的文件。 |
| 鼠标转点菜单中的其他项目时，原版 focusout 微任务看到临时 BODY，提前关闭菜单 | 在菜单项 mousedown 中同步完成焦点转移，保留原生 blur 与最终 click | 避免鼠标松开落到后面面板，造成打开目录、移除等动作未执行。 |
| 对已选记录点“查看内容”没有可见变化 | 将结果区定位到顶部并聚焦，读取失败的当前历史可重新读取 | 让该操作无论是否已经选中都有明确结果。 |

完整结果原子写入 `.data/task-results/<SHA-256(id)>.json`（服从 `WHISPER_DATA_DIR`）。实时状态仍只传轻量历史索引，不把所有历史正文放进每次更新；浏览器最多缓存八份结果，并防止快速切换时迟到响应覆盖当前记录。

新增读取接口 `GET /api/history/:historyId/result` 与历史导出接口 `GET /api/history/:historyId/files/:kind`。已有任务操作和下载、转写、翻译调度流程保持不变。历史中的目录和媒体操作使用所展示结果的路径。

旧记录优先使用已有输出目录中的任务元信息、原文/译文 JSON、TXT、SRT、VTT 和 worker 日志恢复。仅读取登记目录内的已知文件，并核对元信息中的任务 ID。缺失或不完整恢复不写成永久快照，补回文件后可重新读取。过去未保存、已经删除的翻译日志等内容无法凭空恢复，界面会说明缺失；新完成任务保存当时完整结果。移除历史或清空历史不删除输出文件。

## 三点菜单的真实鼠标回归

此前程序先 focus 再 click 的检查未覆盖浏览器默认鼠标焦点转移。新增检查使用实际鼠标移动、按下、松开事件，并通过 DOM 命中与事件顺序定位问题，没有读取屏幕或图像。

修复前报告 `history-menu-before-2026-10-19.json` 中，实色与玻璃两种模式均复现：第二项 mousedown 后菜单关闭，pointerup/click 落到后面的记录卡片，未发送打开目录请求。应用适配修复位于 `glass/lens-menu-adapter.ts`，没有修改上游源码、屏蔽 focusout 传播或在按下时提前执行操作。

修复后报告 `history-menu-fixed-2026-10-19.json` 三组检查全部通过：两种材质下的查看内容、查看同一记录、打开指定历史目录、移除记录及实时列表更新；键盘导航和 Enter 执行、跳过无目录的禁用项、目录缺失时显示错误、鼠标切换下拉选项。报告冻结构建摘要为 `0dad067f01254ec8f85d69c268aeb804fdb6393c78fdb7c60ba087b94745c810`。类型检查与前端构建通过，浏览器错误、未知 API 和外部请求均为零。文件操作只到隔离 HTTP 数据，不打开真实目录或删除实际记录。
