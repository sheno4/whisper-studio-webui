# 任务操作与完整删除

2026-10-20 使用 emil-design-eng 重新审查任务列表、历史菜单、阅读区和确认框的操作逻辑。继续使用原版 Lens 控件，由应用层统一行为。

| 没有媒体仍提供定位，导出菜单全部为空 | 定位要求具体媒体路径，没有可导出文本时禁用导出菜单 | 不提供必然失败或全空的操作。 |

`TaskActions` 在列表菜单和阅读区复用同一套动作。历史的文件操作使用该历史结果的路径；管理操作以最新同 ID 队列状态为准，不把旧历史结果视为当前运行状态。

完整删除使用 `DELETE /api/tasks/:taskId/data` → `TaskManager.deleteTask`。旧 `/output` 入口代理相同的完整删除行为；原有仅移出队列、移除历史及清空历史 API 保留兼容能力，界面不再提供两种易混淆的单项局部删除。

服务端先检查所有登记目录、当前运行状态和共享引用，再执行删除；正在排队、执行或收尾的任务不能删除，删除期间也不能重试。原始本地文件和其他任务引用的内容受到保护。现存输出目录若已超出当前配置输出根，或经过 junction、符号链接，操作会报出具体原因，不会静默误删。已经不存在的目录不会阻止清理记录。

启动的老化清理也尊重当前任务、历史和旧完整结果中的文件引用。删除与验证不主动处理用户现有数据；只有用户确认具体任务后才执行完整删除。
