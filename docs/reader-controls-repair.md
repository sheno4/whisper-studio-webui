# 阅读格式控件位置修复

原版布局将搜索框、条件出现的查找导航和阅读格式开关放在同一条可换行的 flex 布局里。开启“分段阅读”时才挂载“时间戳”，控件组突然变宽，把刚点击的开关顶走；搜索内容变化也会触发相同的挤压。日志模式还会卸载整组开关，切回来重新创建。

| 修改前 | 修改后 | 原因 |
| --- | --- | --- |
| 开启分段时才插入时间戳开关 | 两个开关始终保留；时间戳在不能使用时禁用 | 开关组宽度与节点身份不随状态改变。 |
| 搜索、查找导航和格式选项在一条 flex 中竞争宽度并换行 | 搜索与格式选项固定同一行；查找导航在既有阅读工具栏内保留位置 | 查询出现和清空不挤动格式控件，也不额外建立格式行。 |
| 日志模式跟随正文过渡的延迟值卸载格式组 | 工具栏按当前选择立即禁用，保留原位置与选中值 | 切回正文时恢复同一组控件，不再延迟跳变。 |
| 窄容器中标签与开关自由换行 | 窄容器标签固定放在各自的 72px 开关上方，搜索与开关仍在同一排 | 不通过状态相关换行或位移动画掩盖布局变化。 |

正文保留既有可打断内容过渡。原版 Lens 开关的拇指运动、玻璃材质和手势不变；没有修改后端 API 或上游组件源码。

## 验证

隔离 Chrome 使用冻结的前端构建和模拟任务数据，记录开关轨道及按钮 DOMRect、节点身份和真实 CDP 鼠标事件。探针不把拇指应有的滑动计作控件位移，不截图、不识别图像、不读取像素，不执行真实后端操作。

旧版 `reader-controls-baseline.json` 确认：1440px 和 1024px 窗口中开启分段后按钮左移 125px；480px 窗口中左移 275px、下移 53px。在相同坐标连续点击两次时，第二次因此无法关闭分段。搜索结果和日志切换也造成移位或重新挂载。

早期两行修复的记录保留在 `reader-controls-fixed-2026-10-20.json`，不能作为当前同行布局的验收。当前验收另外检查搜索框与轨道的垂直重叠、格式区单行高度及横向溢出，同时验证切换和搜索期间的节点身份、同坐标连续开关及正文行为。测试只说明对应事件和几何行为，不代表人工视觉或显卡性能验收。

`reader-controls-inline-final-2026-10-20.json` 的 5 组检查全部通过，覆盖 1440、1024、480、320px 窗口，以及玻璃模式。1118 次采样中轨道位置和尺寸最大变化为 0px；320px 窗口中搜索框宽 69px，轨道保持 72×42px，二者垂直重叠 42px，容器 scrollWidth 与 clientWidth 均为 235px。搜索和格式控件始终同排，没有横向溢出。浏览器错误、未知接口、外部请求和修改接口调用均为 0。
