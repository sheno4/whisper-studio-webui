# YouTube 公共下载与按需登录

2026-10-23 修复普通视频被错误引导登录的问题。

| 原行为 | 修改后 | 原因 |
| --- | --- | --- |
| 自动模式先读取 Firefox、Chrome 和 Cookie 文件，最后才匿名尝试 | 首先独立匿名解析，成功时完全不枚举登录来源 | 普通视频不应受浏览器配置、Cookie 数据库占用或缺失文件影响。 |
| 指定浏览器或 Cookie 文件后，公共访问也依赖该来源 | 这些设置只决定确实需要身份验证时使用哪个来源 | 避免把会员功能变成所有视频的前置条件。 |
| 所有解析异常都提示登录或会员不足 | 区分网络、403、格式、链接、会员、年龄和站点身份验证 | 不把连接失败误解释为账号权限问题。 |
| 匿名预解析成功，下载时才遇认证拦截就报登录失效 | 此时按需尝试一次登录来源，并复用得到的内存会话 | 覆盖解析与实际下载要求不同的情况，避免无限重读浏览器。 |
| 泛化的 CookieLoadError 隐藏真实原因 | 保留异常链到错误详情 | 可以分辨文件缺失、数据库占用及其他读取错误。 |

`none` 始终匿名；显式浏览器只使用所选浏览器及配置目录；`file` 只在确实需要认证后检查文件。自动模式需要认证时保持 Firefox、Chrome、已有 Cookie 文件的顺序，单个浏览器配置出错不会阻断后续来源。仅在所有来源都无法读取时提示 Cookie 读取失败；已经得到的真实权限或站点验证结果不会被后续读库失败掩盖。

匿名预解析的网络或解析异常保留直接下载重试机会；已经尝试认证后的网络故障保留具体错误，不重新开始一轮账号读取。裸 403 不触发账号读取，也不被解释为会员不足。没有加入新的第三方下载通道，会员内容不会被转发给匿名镜像。Cookie 保持只读、内存复用及 YouTube/Google 域名过滤。

设置页与 README 同步说明“公开视频先匿名、账号按需使用”，README 的设置入口修正为“设置 → 下载”。[yt-dlp 官方文档](https://github.com/yt-dlp/yt-dlp/wiki/Extractors#exporting-youtube-cookies)将账号用于需要权限的内容；[PO Token 说明](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide)也说明媒体 403 并不等同于会员权限不足。

按用户“不要测试”的要求，本次仅审查代码与调用路径，未执行测试用例、真实视频解析或下载，也没有读取浏览器登录信息。已有回归用例源码随新语义调整，未运行；不据此声明任何公开视频已经实测下载成功。
